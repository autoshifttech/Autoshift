# Deploying AutoShift on Render

`render.yaml` (repository root) is a Render Blueprint with two services:

| Service | What | Custom domain |
|---|---|---|
| `autoshift-web` | The website and business app (Next.js, standalone server) | `www.autoshift.tech`, `autoshift.tech` |
| `autoshift-api` | The API (FastAPI, `backend/Dockerfile`) | `api.autoshift.tech` |

Both run in Singapore on the Starter plan, which never sleeps. The Free plan sleeps after 15 minutes
without traffic, which delays WhatsApp webhooks and stops the API's background jobs. Change `plan`
before applying the Blueprint if you want something else.

The database stays on Supabase. n8n stays where it is (the VPS in `deploy/vps`). The automation timer
stays on cron-job.org; its URLs keep working once `www.autoshift.tech` points at Render.

## 1. Create the services

1. Render → **New → Blueprint** → connect GitHub → pick `autoshifttech/autoshift`, branch `main`.
2. Render reads `render.yaml` and asks for every value marked `sync: false`. Copy each one from
   Vercel (Settings → Environment Variables) or from the backend `.env`:
   - Same values as Vercel: Supabase URL and keys, `ENCRYPTION_KEY` (must not change),
     `AUTOMATION_CRON_SECRET`, `META_APP_SECRET`, `META_APP_ID`, `NEXT_PUBLIC_META_APP_ID`,
     `NEXT_PUBLIC_META_ES_CONFIG_ID`, `META_WEBHOOK_VERIFY_TOKEN`, `META_SYSTEM_USER_TOKEN` (optional).
   - API: `SUPABASE_URL` (= the project URL), `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`,
     `ENCRYPTION_KEY` (same as the website), `SELLER_STATE_CODE`, Razorpay keys (can stay empty for now).
     Leave `SUPABASE_JWT_SECRET` empty.
   - `INTERNAL_SECRET` is generated by Render and copied into the website automatically.
3. Apply. The first deploy takes about 5–10 minutes.

## 2. Test on the Render addresses (before touching DNS)

- `https://autoshift-web.onrender.com` → the home page, `/login`, and **View demo**.
- `https://autoshift-api.onrender.com/health` → `{"status": "ok"}`.
- Supabase → Authentication → URL Configuration → add `https://autoshift-web.onrender.com/**`
  to Redirect URLs, then sign in on the Render address.

## 3. Move the domain

At your DNS provider (remove any old Vercel records for the same names first, and any AAAA records):

| Type | Name | Value |
|---|---|---|
| A | `@` (autoshift.tech) | `216.24.57.1` |
| CNAME | `www` | `autoshift-web.onrender.com` |
| CNAME | `api` | `autoshift-api.onrender.com` |

If `api` currently points at the VPS, this moves the API to Render; keep the `n8n` record on the VPS.
In Render, each custom domain shows **Verified** and a certificate once DNS has spread (minutes to a
few hours). Then remove the domains from the Vercel project and pause or delete it.

## 4. After the move

- Meta webhook (`https://www.autoshift.tech/api/whatsapp/webhook`) and cron-job.org keep their URLs.
- Every push to `main` deploys both services.
